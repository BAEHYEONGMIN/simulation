# 요약 품질 고도화 통합 전략서

작성일: 2026-03-27  
대상: `chat_new.py` 기반 rolling summary + memory extraction + RAG 회상 파이프라인

---

## 1. 문서 목적

이 문서는 다음 두 축을 하나로 통합한다.

1. 제안된 고급 요약 아이디어 6종
2. 현재 코드베이스/평가 구조를 고려한 현실적인 적용 순서, 리스크, 검증 기준

핵심 목표는 다음과 같다.

- 회상 정확도 상승 (사실 누락/왜곡 감소)
- 요약의 맥락 품질 상승 (단절/건조함 감소)
- 운영 안정성 확보 (비용/복잡도/오버피팅 통제)

---

## 2. 현재 상태 진단 (요약)

현재 파이프라인 특성:

- 단일 `summary_prompt_template.txt`로 모든 대화 유형을 요약
- rolling 구조로 이전 요약 + 새 블록 결합 재요약
- bridge(이음새) 2턴으로 연결성 보강
- 회상 시 docs + summary를 함께 활용

관찰된 문제:

- 상태 승격 왜곡: `예정 -> 진행중` 같은 과해석 가능
- 주제별 요약 형태 부적합: 기술/감정 대화를 동일 템플릿 처리
- 평가 분해도 부족 시 원인 추적 어려움 (검색 실패 vs 요약 실패)
- 요약 품질이 장기 회상 품질을 좌우 (AI 발화 비임베딩 비중 존재)

---

## 3. 제안 아이디어 6종 분석

## 3.1 Intent 기반 동적 요약 프롬프팅

요지:

- 블록 요약 전, 경량 분류기로 대화 장르(intent) 판별
- intent별 요약 템플릿 분기

예시 분기:

- 기술/업무: 문제, 시도, 결과, 후속 액션
- 감정/일상: 감정 변화, 공감 포인트, TMI

장점:

- 정보 손실/잡음 감소
- 회상 시 “필요한 형태”로 요약이 남음

리스크:

- 오분류 시 요약 품질 악화

권장:

- 2분류(TECH vs SOCIAL)부터 시작
- 불확실도 높으면 기본 템플릿 fallback

---

## 3.2 Chain of Density (CoD) 요약

요지:

- 1회 생성이 아니라 밀도 강화 단계(초안 -> 엔티티 보강 -> 압축)

장점:

- 엔티티 보존율 상승 (고유명사/숫자/시간)
- 짧은 토큰으로 높은 검색 적합도 가능

리스크:

- 비용/복잡도 증가
- 튜닝 실패 시 오히려 과압축으로 맥락 손실

권장:

- 전면 적용보다 회상형 블록에 선택 적용
- max 2-pass로 제한

---

## 3.3 다중 시점(Multi-Perspective) 요약

요지:

- 동일 블록을 2개 시점으로 저장
  - User Journal
  - Sua Action Item

장점:

- 캐릭터 몰입감/정서적 맥락 강화

리스크:

- 추론/해석 비중 증가로 사실 왜곡 가능성 상승
- 현재 “근거 중심 요약”과 정책 충돌 가능

권장:

- 현재 단계는 보류
- 정책 분리(사실 요약 vs 감성 요약) 후 제한적 도입

---

## 3.4 Bridge(이음새) 품질 강화

요지:

- 단순 원문 2턴 연결 대신 전이 문장(transition) 생성

장점:

- 블록 절단감 완화
- rolling summary의 서사 연속성 향상

리스크:

- 전이 문장 자체 환각 가능

권장:

- “전이 문장 1줄 + 새 사실 추가 금지” 강제 규칙 적용

---

## 3.5 텍스트 요약 + 지식 그래프 하이브리드

요지:

- 요약 텍스트와 함께 `(주체)-[관계]->(객체)` 트리플 저장

장점:

- 팩트 안정성 강화
- 장기 회상/검증에서 강력

리스크:

- 구현 난이도 높음 (스키마, 충돌 병합, 버전 관리)
- 초기 운영 부담 큼

권장:

- 장기 과제로 유지
- memory_store 안정화 후 착수

---

## 3.6 Self-Correction 요약 품질 점검

요지:

- 요약 생성 후 자기 평가(누락/왜곡 점검)
- 불합격 시 1회 재작성

장점:

- 품질 편차 완화
- “대충 요약” 감소

리스크:

- 비용 증가
- 합격 기준 설계 필요

권장:

- 라이트 버전 도입 (재작성 1회 제한)
- 비동기 백그라운드에서만 수행

---

## 4. 통합 실행 우선순위

Phase A (즉시, 성공확률 높음)

1. Intent 기반 템플릿 분기 (2분류)
2. Bridge 전이 문장 1줄 도입
3. Self-Correction 라이트(1회)

Phase B (실험)

4. CoD 선택 적용 (회상형 블록 우선)

Phase C (장기)

5. Multi-Perspective 요약
6. Summary + Knowledge Graph 하이브리드

---

## 5. 설계 원칙 (오버피팅 방지)

1. 모델/검색 로직을 샘플 통과용으로 비틀지 않는다.
2. 평가는 “측정 정밀도 향상” 중심으로만 개선한다.
3. alias/정규화는 도메인 표기 변형에 한정한다.
4. pass rate 단일 숫자보다 실패 유형 분해를 우선한다.

---

## 6. 품질 지표 체계 (권장)

기본 지표:

- Route Accuracy
- Docs Expected Pass
- Summary Expected Pass
- Forbidden Leakage Rate

요약 특화 지표:

- Fact Precision: 요약 사실 중 원문 근거 존재 비율
- State Transition Accuracy: planned/ongoing/done 승격 정확도
- Speaker Attribution Accuracy: 화자 귀속 정확도
- Entity Recall: 원문 핵심 엔티티 회수율

운영 지표:

- 요약 생성 지연(P50/P95)
- 재작성률(Self-Correction trigger rate)
- 블록당 토큰 사용량

---

## 7. 프롬프트/파이프라인 개편 예시

## 7.1 Intent 분류 프롬프트 (경량)

입력: 새 블록 10턴  
출력: `TECH | SOCIAL | MIXED` + confidence

규칙:

- 기술 용어/문제해결 중심이면 TECH
- 감정/일상 상호작용 중심이면 SOCIAL
- 혼합이면 MIXED

## 7.2 Intent별 요약 템플릿

TECH 템플릿:

- 문제 상황
- 시도한 해결책
- 결론/현재 상태
- 다음 액션

SOCIAL 템플릿:

- 주요 감정 변화
- 상호작용 포인트
- 개인 맥락(TMI/취향/계획)

## 7.3 Self-Correction 평가 프롬프트

입력:

- 원문 블록
- 후보 요약

출력:

- `PASS | FAIL`
- 누락 엔티티 목록
- 왜곡 문장 목록
- 재작성 필요 여부

정책:

- FAIL이면 1회만 재작성
- 2회 실패 시 원본 요약 저장 + low_confidence 태그

## 8. 데이터 저장 전략

요약 저장 필드 확장 권장:

- `summary_intent`
- `summary_confidence`
- `quality_grade` (high/medium/low)
- `state_transition_flags` (승격/유지/강등)
- `source_block_range`

향후 KG 확장 대비:

- 요약 텍스트와 별도 `triples_json` 필드(옵션)

---

## 9. 위험요소와 대응

1. 비용 상승

- 대응: intent 분류는 경량 모델, correction 1회 제한

2. 지연 증가

- 대응: 전부 백그라운드 처리, 사용자 응답 경로와 분리

3. 복잡도 증가

- 대응: 단계별 rollout, 각 단계별 canary 샘플 검증

4. 감성 강화로 인한 사실 왜곡

- 대응: 사실 요약/감성 요약 저장 분리

---

## 10. 2주 실행 플랜 (실행형)

Week 1

- Day 1~2: Intent 분류기 + 템플릿 분기
- Day 3: Bridge 전이 문장 도입
- Day 4~5: Self-Correction 라이트

Week 2

- Day 1~2: 지표 대시보드(분해 지표)
- Day 3~4: CoD 선택 적용 A/B
- Day 5: 결과 리뷰 + 다음 phase 결정

1. Intent 분기
