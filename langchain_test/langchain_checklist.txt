# 📌 LLM + Supabase + Memory/RAG 설계 문서

---

# 1. 전체 아키텍처 개요

## 기본 흐름

```
사용자 입력
   ↓
(1) 최근 대화 조회 + 요약 조회 + 장기 기억 조회
   ↓
(2) 프롬프트 구성
   ↓
(3) LLM 응답 생성
   ↓
(4) 응답 반환
   ↓
(5) 비동기 후처리
      ├─ 대화 저장
      ├─ 세션 요약 갱신
      └─ 장기 기억 추출
```

---

## 핵심 구성 요소

| 구성                      | 역할       |
| ----------------------- | -------- |
| chat_messages           | 원본 대화 저장 |
| conversation_summaries  | 세션 요약    |
| user_memories           | 장기 기억    |
| vector store (Supabase) | RAG 검색   |
| LangChain               | 파이프라인 관리 |

# 3. Memory 구조 설계

## memory_type 정의

```text
profile       → 사용자 기본 정보
style         → 말투/응답 방식
preference    → 취향
taboo         → 금기/싫어하는 것
relationship  → 캐릭터 관계
fact          → 기타 사실
```

---

## memory_key 예시

```text
profile:
  - user_name

style:
  - preferred_speech_style

preference:
  - favorite_genre

taboo:
  - disliked_topic

relationship:
  - attitude_to_character

fact:
  - current_activity
```

---

## canonical value 예시

```text
preferred_speech_style:
  - polite
  - casual

favorite_genre:
  - fantasy
  - sci_fi

disliked_topic:
  - politics
```

# 5. importance / confidence 설계

## importance (중요도)

백엔드 규칙 기반:

| type         | 점수 |
| ------------ | -- |
| profile      | 9  |
| taboo        | 9  |
| style        | 8  |
| relationship | 7  |
| preference   | 6  |
| fact         | 5  |

---

## confidence (신뢰도)

| 상황     | 값        |
| ------ | -------- |
| 명시적 진술 | 0.9      |
| 반복 확인  | 0.9~0.95 |
| 추론     | 0.6~0.7  |
| 애매함    | 0.4      |

---

## 업데이트 규칙

```sql
confidence = min(0.95, confidence + 0.1)
evidence_count += 1
```

# 1. chat_messages (이미 있음, 보완)

```sql
create table chat_messages (
  id bigserial primary key,
  conf_uid text not null,
  history_uid text not null,
  role text not null,
  content text not null,
  name text,
  avatar text,
  created_at timestamptz default now()
);

create index idx_history
on chat_messages (conf_uid, history_uid);

create index idx_created_at
on chat_messages (created_at desc);
```

# 2. conversation_summaries

```sql
create table conversation_summaries (
  id bigserial primary key,
  conf_uid text not null,
  history_uid text not null,

  summary text not null,
  summary_type text default 'rolling', -- rolling / final

  start_message_id bigint,
  end_message_id bigint,

  message_count int,

  created_at timestamptz default now()
);

create index idx_conv_summary
on conversation_summaries (conf_uid, history_uid, created_at desc);
```

# 3. user_memories (핵심)

```sql
create table user_memories (
  id bigserial primary key,

  user_id text not null,
  conf_uid text not null,

  memory_type text not null,
  memory_key text not null,
  memory_value text not null,

  importance int default 5,
  confidence float default 0.7,

  evidence_count int default 1,

  status text default 'active', -- active / archived

  created_at timestamptz default now(),
  updated_at timestamptz default now(),
  last_seen_at timestamptz default now()
);

create index idx_user_memory
on user_memories (user_id, conf_uid, memory_type, importance desc);
```

# 4. vector store (documents)

```sql
create table documents (
  id bigserial primary key,

  content text,
  metadata jsonb,

  embedding vector(1536)
);
```

---

# 5. similarity search 함수 (Supabase)

```sql
create or replace function match_documents (
  query_embedding vector(1536),
  match_count int
)
returns table (
  id bigint,
  content text,
  metadata jsonb,
  similarity float
)
language sql
as $$
  select
    id,
    content,
    metadata,
    1 - (embedding <=> query_embedding) as similarity
  from documents
  order by embedding <=> query_embedding
  limit match_count;
$$;
```
