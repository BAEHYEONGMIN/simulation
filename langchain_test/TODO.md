# 🚀 RAG 챗봇 프로젝트 진행 현황 및 To-Do List

## ✅ 지금까지 완료된 진행 사항 (Phase 1)
지금까지 우리는 단순한 LLM API 호출을 넘어, **실제 프로덕션 수준의 RAG(검색 증강 생성) 파이프라인 뼈대**를 완벽하게 구축했습니다.

### 1. 🗄️ 데이터베이스 및 인프라 구축
- Supabase Vector DB 연동 완료 (`chat_messages`, `documents_gemini`)
- 벡터 검색용 원격 함수(RPC) `match_documents_gemini` 연결
- AI 응답 추적을 위한 `metadata` 컬럼 추가 및 연결 (RAG 출처 트래킹)

### 2. 🤖 AI 모델 연결 및 최적화
- `google-genai` 최신 SDK 및 LangChain(`ChatGoogleGenerativeAI`) 통합
- 1티어/무료 티어 API 키와 `v1beta` 버전을 활용한 최신 임베딩 모델(`gemini-embedding-001`, 768차원) 적용
- 최신 최고 성능 모델 라인업 장착 (`gemini-3.1-pro-preview`, `gemini-3.1-flash-lite-preview`)

### 3. ⚙️ 코어 로직(chat.py) 완성
- **문서 검색 (Retriever)**: 사용자 입력 임베딩 변환 후 DB에서 유사 문서 Top-3 검색
- **정확도 필터 (Threshold)**: 유사도 0.75 미만의 쓰레기 데이터를 걸러내어 환각(Hallucination) 방지
- **세션 관리**: `conf_uid`와 `history_uid`를 분리하여 단기/장기 기억 묶음 완벽 통제
- **전체 흐름 자동화**: 대화 이력 불러오기 → 프롬프트 조립 → 대답 생성 → DB 자동 저장 (LCEL 체인 구조)

### 4. 📝 프롬프트 엔지니어링 (구조 분리)
- **RESPONSE_POLICY**: TTS 낭독에 최적화된 마크다운 금지, 이모지 금지 등 공통 강제 규칙 하드코딩 (chat.py)
- **CHARACTER_PERSONA**: 캐릭터의 성격과 말투를 지정하는 정체성 프롬프트 하드코딩 (chat.py)
- **디버깅 모드**: 검색된 유사 문서(RAG)와 최종 조립된 프롬프트 전문이 `====` 구분선과 함께 깔끔하게 터미널에 출력

## 📅 앞으로 해야 할 일 (Phase 2 & 3 고도화)
이제 RAG와 챗봇의 뼈대는 튼튼하게 세워졌습니다. 여기서 "진짜 똑똑한 AI"로 한 단계 더 진화하기 위한 기능들입니다.

### 🧠 [1순위] 영구 기억(Memory) 및 요약(Summary) 파이프라인
- [ ] **대화 요약 압축 (`conversation_summaries`)**
  - 대화가 10턴 이상 길어졌을 때 과거 대화 원문을 모델(`SUMMARY_MODEL`)에게 넘겨 3문장 이내로 압축 요약시키고 DB에 저장하기 (토큰 비용 극적으로 절감)
- [ ] **장기 기억 추출기 구축 (`user_memories`) - [Pydantic 기반 강제 구조화]**
  - 사용자의 성향, 호불호, 프로필 정보 등을 대화 속에서 파악하여 `user_memories` DB에 Key-Value 형태로 영속 저장하기 (예: `favorite_genre: fantasy`)
  - 💡 **스터디 연계:** `with_structured_output`과 `Pydantic`을 활용하여, LLM의 쓸데없는 잡담을 원천 차단하고 오직 정해진 JSON 스키마(Key-Value 구조) 형태로만 추출결과가 반환되도록 응답 파싱 강제하기.
- [ ] **장기 기억 주입 프롬프트 갱신**
  - 템플릿에 `[사용자 장기 기억]` 섹션을 새로 뚫고, 사용자 관련 기억을 DB에서 읽어내어 시스템 프롬프트에 주입하기

### 🚦 [2순위] 지능형 라우팅 및 고급 검색 아키텍처
- [ ] **검색 필요성 초고속 판별 (Semantic Routing)**
  - "안녕?", "잘 자" 같은 단순 일상 대화는 RAG 임베딩 및 검색 파이프라인을 타지 않도록 회피 처리하기 (비용 및 응답 속도 최적화)
  - 💡 **스터디 연계:** 느린 LLM 호출 대신, 미리 정의된 카테고리 샘플들과의 임베딩 거리(Cosine Similarity) 측정만으로 **0.01초 만에 길을 가르는 룰베이스+벡터 초고속 시맨틱 라우팅** 기법 적용하기.
- [ ] **검색용 쿼리 재작성 및 확장 (Multi-Query Retriever)**
  - 💡 **스터디 연계:** 사용자가 대명사로 "그 주인공이 뭐했어?" 라고 뭉뚱그려 말할 때, 문맥을 파악해 3~4개의 구체적인 질문("로맨스 소설 남주인공 행동" 등)으로 쪼개서(Rewrite) 다방면에서 찔러 점수를 병합하는 고급 검색 도입하기.
- [ ] **대화 맥락 보존 검색 (Parent Document Retriever)**
  - 💡 **스터디 연계:** 단어 단위 명중률을 높이기 위해 아주 잘게 쪼갠 조각(Chunk) 단위로 정교하게 벡터 유사도 검색(Top-1)을 하되, 검색이 성공하면 `related_message_id`를 추적해 해당 조각이 원래 있던 앞뒤 대화 5개(Parent)를 통째로 가져와서 LLM 프롬프트에 제공함으로써 '문맥 단절 현상' 근본적으로 해결하기.
